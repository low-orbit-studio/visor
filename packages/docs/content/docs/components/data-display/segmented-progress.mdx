## Step labels

Pass `steps` to put a label under each segment. A done step's label carries a check, the current
step's reads bold in the primary ink, and a step not reached reads in the tertiary ink. On mount
each filled segment draws in from the left, once, about 140ms after the one before it; under
`prefers-reduced-motion` the fills are drawn static.

A step without a `state` follows `value` and `current`, so
`<SegmentedProgress value={1} current={1} steps={[{ label: 'A' }, { label: 'B' }, { label: 'C' }]} />`
draws done, current, pending.

## Theming the steps

| Hook | Default | Drives |
| --- | --- | --- |
| `--button-strong-fill` | `--interactive-primary-bg` | The current segment's fill, with or without `steps` |
| `--segmented-progress-sm-label-font-size` | `--font-size-xs` (12px) | Labels under `sm` |
| `--segmented-progress-md-label-font-size` | `--font-size-sm` (14px) | Labels under `md` |
| `--segmented-progress-fill-duration` | `600ms` | Each segment's fill-in |
| `--segmented-progress-fill-stagger` | `140ms` | The delay between one segment's fill and the next |

A host that wants smaller labels at desktop widths sets the label hooks in its own media or
container query.

## Installation

```bash
npx visor add segmented-progress
```

This copies two files into your project:

- `components/ui/segmented-progress/segmented-progress.tsx` — the component
- `components/ui/segmented-progress/segmented-progress.module.css` — the styles

## Usage

```tsx
import { SegmentedProgress } from '@/components/ui/segmented-progress/segmented-progress';

export default function OnboardingProgress({ step, total }: { step: number; total: number }) {
  return (
    <SegmentedProgress
      total={total}
      value={step}
      current={step}
      aria-label={`Step ${step + 1} of ${total}`}
    />
  );
}
```

## Accessibility

- Without `steps`, the root element has `role="progressbar"` with `aria-valuemin={0}`, `aria-valuemax={total}`, and `aria-valuenow={value}`.
- With `steps`, every step is `aria-hidden` and a visually hidden line beside the bar is read instead: "Step 2 of 3: Bank Details" by default, naming the failed step first, then the current one, then the next one ("All 3 steps done" when every step is done). Pass `summary` to say it differently.
- Without `steps`, an `aria-label` is required — describe the current step context (e.g. `"Step 3 of 10"` or `"Brand elicitation: step 3 of 10 complete"`).
- Individual segment `<span>` elements are presentational; the progressbar role carries all announcements.
- Segment transitions and the fill-in animation are disabled under `prefers-reduced-motion`.
