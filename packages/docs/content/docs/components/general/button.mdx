### Dialog footer (`dlg`)

The compact `size="dlg"` face is the dialog-footer button from the Animal
dialog substrate — 11px/600 text, tokenized ~8/12px padding, `radius-lg`. Its
three intents reuse the variant axis: primary via `variant="default"`, cancel
via `variant="ghost"` (renders a hairline-outlined, secondary-ink face at `dlg`
size), and destructive via `variant="destructive"` (renders a subtle-danger
face at `dlg` size). Pair it with the [Dialog Form](/docs/blocks/dialog-form)
block.

## Gated State

A permission-gated button is visually dimmed but remains hover-able, surfacing a tooltip that explains why the action is unavailable. Unlike the native `disabled` state, the button stays in the tab order so assistive technology users can discover the reason.

Use `gated` to apply the visual state, and `gatedReason` to provide the tooltip text. A `TooltipProvider` ancestor is required when `gatedReason` is set.

The `gated` prop uses `aria-disabled="true"` instead of the native `disabled` attribute, so the button stays keyboard-focusable. Click handlers are suppressed internally — no need to guard them in your code.

## Pending State

`pending` reports that the button's action is in flight. It paints a busy glyph, sets `aria-busy="true"`, and suppresses activation so the action cannot be double-submitted — without ever changing the control's geometry.

**Holding the box is the point.** The idle children stay in place at zero opacity and the glyph paints over them, so the button keeps its width and its height. A pending state that swaps `Save` for `Saving…` on a content-sized button resizes the control and shoves every sibling in a `justify-content: flex-end` footer — which is the visible defect this prop exists to remove, not a cosmetic detail.

<ComponentPreview

### Two thresholds, so it reads as progress

| Threshold | Default | Theme property | Prop |
| --- | --- | --- | --- |
| Delay before painting | `200ms` | `--button-pending-delay` | `pendingDelay` |
| Minimum time on screen | `300ms` | `--button-pending-min-duration` | `pendingMinDuration` |

An action that resolves in 150ms shows nothing at all. An action that resolves in 250ms shows the glyph for long enough to be legible instead of flashing for a single frame. Neither custom property is declared on the component's own class, so a theme's `:root` value is not shadowed.

### Accessibility contract

- `aria-busy="true"` is set while the action is in flight. A label change alone is **not** announced, which is why the attribute carries the signal.
- The **accessible name does not change**. `pendingLabel` is decorative (`aria-hidden`), so the control is not renamed mid-action.
- `pending` does **not** set the native `disabled` attribute — like `gated`, it uses `aria-disabled` so the button stays focusable. It is the user's focus anchor while they wait.
- Button deliberately does not invent a `role="status"` region. Pair it with your own when the message needs to be spoken.
- The glyph is the [Spinner](/docs/components/general/spinner) primitive, which pauses under `prefers-reduced-motion`.

```tsx
const [saving, setSaving] = React.useState(false);

async function handleSave() {
  setSaving(true);
  try {
    await save();
  } finally {
    setSaving(false);
  }
}

<Button pending={saving} onClick={handleSave}>
  Save changes
</Button>;
```

<Callout type="info">
  Under `asChild` the state attributes and the activation suppression still apply,
  but no chrome is injected — Slot takes a single child, so there is nowhere to put
  the overlay. Render a real `<button>` when you need the glyph.
</Callout>

## Installation

```bash
npx visor add button
```

- `components/ui/button/button.tsx` — the component

## Source Files

After running `npx visor add button`, you'll have:

### `button.tsx`

```tsx
import * as React from "react";
import { cva, type VariantProps } from "class-variance-authority";
import { cn } from "@/lib/utils";
import styles from "./button.module.css";

const buttonVariants = cva(styles.base, {
  variants: {
    variant: {
      default: styles.variantDefault,
      secondary: styles.variantSecondary,
      outline: styles.variantOutline,
      ghost: styles.variantGhost,
      destructive: styles.variantDestructive,
    },
    size: {
      sm: styles.sizeSm,
      md: styles.sizeMd,
      lg: styles.sizeLg,
    },
  },
  defaultVariants: {
    variant: "default",
    size: "md",
  },
});

export interface ButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof buttonVariants> {
  asChild?: boolean;
}

const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ className, variant, size, ...props }, ref) => {
    return (
      <button
        className={cn(buttonVariants({ variant, size }), className)}
        ref={ref}
        {...props}
      />
    );
  }
);
Button.displayName = "Button";

export { Button, buttonVariants };
```

### `button.module.css`

All styles use CSS custom properties from `@loworbitstudio/visor-core`, so the button automatically adapts to your active theme.

## Customization

After copying the component, you own it completely.

A busy state is **not** a customization — use the built-in [`pending`](#pending-state)
prop. Hand-rolling one is how a codebase ends up with thirty different busy flags,
each resizing its own control:

```tsx
// Don't — this resizes the button and announces nothing
{saving ? "Saving…" : "Save"}

// Do
<Button pending={saving}>Save</Button>
```

Genuine customizations are new variants and sizes — add a branch to the CVA
config and a matching class in `button.module.css`:

```tsx
const buttonVariants = cva(styles.base, {
  variants: {
    variant: {
      // ...existing variants
      success: styles.variantSuccess,
    },
  },
});
```
