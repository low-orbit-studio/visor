## Default

The text, then a pencil. Click either one (or press Enter on the pencil) and an input takes the text's place at the same size, so nothing below it moves. A long title wraps; it is never truncated.

## Without the pencil

Pass `pencil={false}` when the design draws the text alone. The text is then the control: a native `button` named `Edit {label}, {value}` (override the lead with `editLabel`), reachable by Tab, opened by click, Enter or Space, and given focus back after Enter or Escape. Hover underlines it, and keyboard focus draws the focus ring alone (an underline under the ring read as a double line), so it still reads as editable: the underline on hover, the ring on focus. The padding that clears the ring is present in every state and cancelled by a negative margin, so nothing shifts. The underline is solid; a theme that wants a dashed one sets `--inline-edit-underline-style: dashed` (never dotted). The hit target is at least 24px tall.

## Saving to a server

`onCommit` may return a promise, such as a server action's. While it runs, the field stays open, read-only and marked `aria-busy`, its text in the secondary ink. When it resolves, the field closes and focus goes back to the pencil (or stays where Tab or a click took it). If it rejects, or resolves to `{ error: string }`, the message shows under the field the way [FieldError](/docs/components/form/field) shows one, the input draws the error edge and keeps what was typed, and Enter tries again. Escape gives up and restores `value`. Try a title containing "fail".

## Keyboard

| Key | Action |
| --- | --- |
| `Enter` or `Space` (on the pencil, or on the text when `pencil={false}`) | Opens the input, with the text selected |
| `Enter` | Commits, and returns focus to the pencil (or the text) |
| `Tab` | Commits, and moves on to the next field |
| `Escape` | Restores the text without committing (after a failed save, too) |

Blur commits too. `onCommit` receives the trimmed text, and is not called when nothing changed.

## Edges

At rest, InlineEdit is text and a pencil, with no edge. While editing, the input draws its resting edge from the shared [control-edge tokens](/docs/themes/component-tokens), never from `border`, so `--control-edge-width: 0` turns it off with every other form control. Focus still draws its own ring.

## Theming

The pencil is the same mark as an icon-only [Button](/docs/components/general/button): it reads `--button-icon-size` (the glyph), `--button-icon-pad` (the hit target, drawn on `::before` so it adds no height to the line) and `--button-icon-ghost-color` (the ink at rest). The default's muted colour is `--text-tertiary`. With `pencil={false}`, the text button's hover underline reads `--inline-edit-underline-style` (default `solid`).

The input (and the text button when `pencil={false}`) takes its size, weight and line height from `font: inherit`, which comes from Visor's element reset (`@import "@loworbitstudio/visor-core/reset"`), as it does for every form control. Tailwind's preflight sets the same thing. Without either, the browser's 13px control font shows, in InlineEdit and in every other Visor control.

A failed save's edge reads `--control-invalid-ring-color` (falling back to `--border-error`), and its message `--text-error`, like FieldError.

## When not to use

- Multi-line text: use [Textarea](/docs/components/form/textarea).
- A labelled card tile with a save button: use [EditableBlock](/docs/components/general/editable-block).

npx visor add inline-edit

- `components/ui/inline-edit/inline-edit.tsx`: the component
- `components/ui/inline-edit/inline-edit.module.css`: the styles
