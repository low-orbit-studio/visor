## With onChange

`onChange` emits an E.164 string only when the number is complete and valid. Anything
else emits `null` — type a few digits below and watch the emitted value stay `null`
until the number is whole.

## Validation on blur

The library's error callback does not fire while a number is still partial, so
`onBlur` reports the validation error directly. A visibly-present partial that saves
as nothing is silent data loss — surface it.

<ComponentPreview
  title="Validation on blur"
  code={"<PhoneInput\n  name=\"phone\"\n  onBlur={(error) => {\n    // e.g. \"TOO_SHORT\" — null when empty or valid\n    setError(error);\n  }}\n/>"}

`<button>` and opens on click. Pair it with `countrySelectorMode="OFF"` for a true

## Installation

```bash
npx visor add phone-input
```

This copies three files into your project:

- `components/ui/phone-input/phone-input.tsx` — the component
- `components/ui/phone-input/phone-input.css` — theme bindings for intl-tel-input
- `components/ui/phone-input/phone-input.module.css` — wrapper styles

It also installs `intl-tel-input` and `@intl-tel-input/react` as dependencies.

**Important:** Import the global CSS file in your app layout or entry point:

```tsx
import '@/components/ui/phone-input/phone-input.css';
```

## Usage

```tsx
import { PhoneInput } from '@/components/ui/phone-input/phone-input';

function MyForm() {
  const [phone, setPhone] = useState<string | null>(null);
  const [isValid, setIsValid] = useState(false);

  return (
    <PhoneInput
      name="phone"
      value={phone}
      onChange={(e164, valid) => {
        setPhone(e164);
        setIsValid(valid);
      }}
    />
  );
}
```

`phone` is either a valid E.164 string or `null` — it is never a partial, so it is safe
to persist directly.

## Features

- **Country code selection** — searchable dropdown with all countries and dial codes
- **E.164 safe** — `onChange` emits a valid E.164 string or `null`, never a partial number
- **Format-as-you-type** — applies per-country formatting rules as users type; the display keeps the user's partial typing even while the emitted value is `null`
- **Paste detection** — pasting a foreign number switches the selected country automatically
- **Validation** — powered by libphonenumber, with the error surfaced on blur
- **SSR-safe** — renders a plain `<input type="tel">` on the server and hydrates in place

## Theming

The country dropdown is themed by binding the library's own CSS custom properties to
Visor tokens, so every theme is correct with no consumer-side CSS:

| Library variable | Visor token |
|---|---|
| `--iti-country-selector-bg` | `--surface-popover` |
| `--iti-border-color` | `--divider` |
| `--iti-icon-color` | `--text-secondary` |
| `--iti-hover-color` | `--surface-interactive-hover` |
| `--iti-strict-reject-flash-color` | `--surface-error-subtle` |

Each binding falls back to the library's own default, so a theme that does not define one
of these tokens renders exactly as the unstyled library does.

## Portaling the dropdown

The country selector is inline by default, which keeps it inside the consumer's theme
scope. If you need it portaled — to escape an `overflow: hidden` ancestor, say — pass the
`portal` prop. It is all-or-nothing on purpose: the container cannot be set without the
theme-scoping class that travels with it.

```tsx
<PhoneInput
  name="phone"
  portal={{ container: document.body, scopeClassName: 'theme-space' }}
/>
```

## Accessibility

- Renders a native `<input>` with `type="tel"` and `autocomplete="tel"` for appropriate mobile keyboard and autofill
- Always pair with a `<Label>` using `htmlFor`/`id`, or provide `aria-label` directly
- The country dropdown supports keyboard navigation and search
- Focus and caret survive parent re-renders — the wrapper skips writing back to the input while it is focused
