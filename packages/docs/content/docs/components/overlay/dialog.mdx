## Bottom sheet on a phone

`presentation` picks how the same content is presented: `dialog` (a centred modal, the default), `sheet` (a bottom sheet), or `responsive` (a dialog from `breakpoint` up, a sheet below it; default 640px). The content, focus trap and Escape handling do not change. The sheet is sized with `dvh` and the visual viewport so the on-screen keyboard never covers it, scrolls a focused field into view, and appears without the slide under `prefers-reduced-motion`. The close button is present unless `showCloseButton={false}`, for content that carries its own dismiss action; `showHandle` adds a drag handle that dismisses on a downward drag, never as the only way out.

```tsx
<Dialog presentation="responsive" breakpoint={640}>
  <DialogTrigger asChild><Button>Add a booking</Button></DialogTrigger>
  <DialogContent showHandle>
    <DialogHeader back={<DialogBack onClick={goBack} />}>
      <DialogTitle>Add a booking</DialogTitle>
    </DialogHeader>
    {/* same content on desktop and phone */}
  </DialogContent>
</Dialog>
```

## Inside a container

Pass `container` (the element itself, held in state) and the overlay and content cover only that element. A scoped dialog is deliberately not Radix modal mode, which aria-hides everything outside and blocks pointer events on `body`: it traps focus inside the content, makes only the container's other children `inert`, and leaves the rest of the page interactive. Only the scrim dismisses on a press. The container gets `position: relative` if it is `static`.

```tsx
const [pane, setPane] = useState<HTMLElement | null>(null)

<section ref={setPane}>
  <Editor />
  <Dialog open={open} onOpenChange={setOpen} container={pane}>
    <DialogContent>
      <DialogHeader><DialogTitle>Sign back in</DialogTitle></DialogHeader>
    </DialogContent>
  </Dialog>
</section>
```

## Back action

`DialogHeader` takes a `back` slot, rendered before the title and opposite the close button. `DialogBack` is a ready-made arrow button labelled "Back" for it.

## Theme Hooks

A theme can skin the panel and the page scrim without leaving Dialog, so the focus trap, scroll lock and Escape still come with it. ConfirmDialog reads the same hooks. Unbound, each one falls back to the value Dialog has always drawn, in both the default and the editorial density.

| Hook | Binds | Unbound |
|---|---|---|
| `--dialog-max-width` | The centred panel's widest. The bottom sheet stays full width. | `32rem` (editorial `480px`) |
| `--dialog-radius` | Panel corners; the bottom sheet's top corners. | `--radius-lg` (editorial `--radius-xl`) |
| `--dialog-bg` | Panel fill. | `--surface-page` (editorial `--surface-popover`) |
| `--dialog-padding` | Panel inset. | `--spacing-6` (editorial `--spacing-8`) |
| `--dialog-shadow` | Panel shadow. | `--shadow-xl` (editorial `--shadow-lg`) |
| `--dialog-backdrop-filter` | Filter on what shows through the panel. | `none` |
| `--dialog-overlay-bg` | The scrim's colour. | `--overlay-bg`, else `rgba(0, 0, 0, 0.8)` |
| `--dialog-overlay-blur` | How much the scrim blurs the page. | `4px` (editorial `2px`) |

A glass edit sheet, bound in the theme under `components.dialog`:

```yaml
# my-theme.visor.yaml
components:
  dialog:
    max-width: "min(760px, calc(100vw - 48px))"
    radius: "56px"
    padding: "48px 56px 40px"
    bg:
      light: "rgb(255 255 255 / 0.72)"
      dark: "rgb(20 21 23 / 0.72)"
    backdrop-filter: "blur(32px) saturate(110%)"
    shadow: "inset 0 0 0 1px rgb(0 0 0 / 0.16), 0 48px 120px -48px rgb(0 0 0 / 0.55)"
    overlay-bg: "rgb(0 0 0 / 0.42)"
    overlay-blur: "6px"
```

Or the same hooks in plain CSS:

```css
:root {
  --dialog-max-width: min(760px, calc(100vw - 48px));
  --dialog-radius: 56px;
  --dialog-padding: 48px 56px 40px;
  --dialog-bg: rgb(255 255 255 / 0.72);
  --dialog-backdrop-filter: blur(32px) saturate(110%);
  --dialog-overlay-bg: rgb(0 0 0 / 0.42);
  --dialog-overlay-blur: 6px;
}
```

Every theme-bindable token is listed on [Component Tokens](/docs/themes/component-tokens#dialog).

## Installation

```bash
npx visor add dialog
```

This copies two files into your project:

- `components/ui/dialog/dialog.tsx` — the component
- `components/ui/dialog/dialog.module.css` — the styles

## Usage

```tsx
import {
  Dialog, DialogTrigger, DialogContent,
  DialogHeader, DialogTitle, DialogDescription,
} from '@/components/ui/dialog/dialog';

<Dialog>
  <DialogTrigger asChild>
    <Button>Open</Button>
  </DialogTrigger>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>Title</DialogTitle>
      <DialogDescription>Description text.</DialogDescription>
    </DialogHeader>
    {/* content */}
  </DialogContent>
</Dialog>
```

## Sub-components

| Component | Element | Purpose |
|-----------|---------|---------|
| `Dialog` | -- (Radix Root) | Root component managing open/close state. |
| `DialogTrigger` | `<button>` | Element that opens the dialog on click. |
| `DialogContent` | `<div>` (portal) | The modal panel with overlay, close button, and animations. |
| `DialogHeader` | `<div>` | Container for title and description at the top. Takes a `back` slot for a leading back action. |
| `DialogBack` | `<button>` | Leading back action for the header (labelled "Back"). |
| `DialogTitle` | `<h2>` | Accessible dialog heading. |
| `DialogDescription` | `<p>` | Secondary text describing the dialog purpose. |
| `DialogClose` | `<button>` | Explicit close trigger (in addition to the built-in X button). |
| `DialogOverlay` | `<div>` | Background overlay behind the dialog. |
| `DialogPortal` | -- | Portal wrapper for rendering outside the DOM tree. |

## Accessibility

- Built on `@radix-ui/react-dialog` with full WAI-ARIA dialog semantics.
- Focus is trapped inside the dialog while open, in both presentations and when scoped to a container.
- `Escape` key closes the dialog; clicking the overlay also dismisses it.
- `DialogTitle` is linked via `aria-labelledby`; `DialogDescription` via `aria-describedby`.
- Focus returns to the trigger element when the dialog closes.
