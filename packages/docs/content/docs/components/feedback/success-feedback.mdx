**Pattern vs Primitive:** `SuccessFeedback` is the Borealis-recommended *pattern* for app-wide success confirmation — it wraps the [Toast](/docs/components/feedback/toast) primitive with spec-mandated defaults (4s auto-dismiss, undo action support, a11y live region). ## Setup

Add `<Toaster />` and `<SuccessLiveRegion />` once in your root layout.

```tsx
// app/layout.tsx
import { Toaster } from '@/components/ui/toast/toast';
import { SuccessLiveRegion } from '@/components/ui/success-feedback/success-feedback';

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        {children}
        <Toaster />
        <SuccessLiveRegion message="" />
      </body>
    </html>
  );
}
```

Call `showSuccess(title, options?)` after any successful operation. The toast auto-dismisses after 4 seconds.

## Success Panel

`SuccessPanel` is the screen at the end of a flow: a round success seal, a heading, a
description, an optional check list and your action, centred. It announces its heading once, on
mount, through a `SuccessLiveRegion` of its own. The seal's icon and each row's icon are slots;
each defaults to a check-circle. Bold runs in a row (`<b>`, `<strong>`) read in the primary ink.

    description="Your bookings, their fees and your payments live on your dashboard."
    items={[
      { content: <><b>Your info</b> is saved.</> },

    ]}

  />

| Hook | Default | Drives |
| --- | --- | --- |
| `--success-panel-heading-font-size` | `--font-size-xl` (20px) | The heading |
| `--success-panel-description-font-size` | `0.9375rem` (15px) | The description |
| `--success-panel-item-font-size` | `--font-size-sm` (14px) | Each check-list row |

A host that wants smaller type at desktop widths sets these in its own media or container query.
The seal fills with `--surface-success-subtle` and draws its icon in `--text-success`.

## Installation

```bash
npx visor add success-feedback
```

This copies two files into your project:

- `components/ui/success-feedback/success-feedback.tsx` — the hook, the live region and the panel
- `components/ui/success-feedback/success-feedback.module.css` — the styles

The pattern depends on the [Toast](/docs/components/feedback/toast) primitive — install that first:

```bash
npx visor add toast
```

## Usage

```tsx
import { useSuccessToast, SuccessLiveRegion } from '@/components/ui/success-feedback/success-feedback';

// In your component
const { showSuccess } = useSuccessToast();

// Basic
showSuccess('Changes saved');

// With description
showSuccess('File uploaded', {
  description: 'report-q4-2025.pdf was saved to your documents.',
});

// With action
showSuccess('Message sent', {
  action: { label: 'Undo', onClick: handleUndo },
});

// Custom duration (clamped to 3000–8000ms)
showSuccess('Settings saved', { duration: 6000 });
```

## API Reference

### `useSuccessToast()`

Returns `{ showSuccess }`.

```tsx
showSuccess(title: string, options?: SuccessToastOptions): void
```

### `SuccessToastOptions`

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `description` | `string` | — | Optional supporting sub-copy beneath the title |
| `action` | `{ label: string; onClick: () => void }` | — | Optional action affordance (e.g. "Undo", "View") |
| `duration` | `number` | `4000` | Auto-dismiss in ms. Clamped to [3000, 8000] per Borealis spec |
| `id` | `string \| number` | — | Explicit id for deduplication (Sonner merges same-id toasts) |

### `SuccessLiveRegion`

<PropsTable component="success-feedback" />

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `message` | `string` | `""` | The success text to announce to screen readers |

`SuccessLiveRegion` also accepts all standard `<div>` HTML attributes.

### `SuccessPanel`

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `heading` | `string` | — | The heading, announced once on mount |
| `description` | `ReactNode` | — | Supporting copy under the heading |
| `icon` | `ReactNode` | check-circle | The seal's icon slot |
| `items` | `{ icon?: ReactNode; content: ReactNode }[]` | — | An optional check list |
| `action` | `ReactNode` | — | Your action, usually a `Button` |

`SuccessPanel` also accepts all standard `<div>` HTML attributes.

## Accessibility

- `SuccessPanel` renders its heading as an `<h2>` and announces it once, on mount, through its own live region. The seal and row icons are hidden from assistive tech.
- `SuccessLiveRegion` renders `role="status"` + `aria-live="polite"` + `aria-atomic="true"` so screen readers announce the message without interrupting the user.
- The Toaster (Sonner) also provides its own `aria-live="polite"` container — both reinforce the announcement.
- Toasts auto-dismiss after 4 seconds. Ensure any critical confirmation is also conveyed inline if the user might miss the toast.
- Sonner respects `prefers-reduced-motion`: animations are suppressed when the OS setting is active.
- The dismiss button in each toast is keyboard-accessible; focus does not jump when a toast appears.

## Composition Rules (Borealis Spec)

Per the [Borealis global state catalog](/docs/patterns/borealis-states):

- **Triggers:** CRUD operations, file upload/export, settings saved, invite sent, link copied
- **Never for errors:** Use inline validation (VI-587) or an error Banner for failures
- **Auto-dismiss:** Default 4s; configurable 3–8s. Timer pauses on hover/keyboard focus (Sonner built-in)
- **Stacking:** Max 3 visible toasts (Sonner default). Oldest is dismissed when the queue exceeds 3
- **Deduplication:** Pass `id` to deduplicate identical messages within a 500ms window
